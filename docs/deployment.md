# 공개 사이트와 업데이트 정보

공개 저장소는 `main` 하나에서 문서, 배포 워크플로와 게시된 Windows 업데이트 정보를 관리합니다.
웹사이트 HTML과 에셋은 Git 브랜치에 커밋하지 않고 GitHub Actions 빌드 산출물로 배포합니다.

## 웹사이트 게시

Actions의 `SIDEY Website deployment`를 `main`에서 수동 실행합니다.
워크플로는 비공개 소스 저장소의 `main`을 읽기 전용으로 가져와 웹사이트를 빌드하고 테스트합니다.
공개 저장소는 실행 시점의 정확한 커밋으로 읽으며, 배포 직전에 `main`이 바뀌었다면 중단합니다.
그때는 최신 `main`에서 다시 실행합니다.

GitHub Pages의 게시 방식은 **GitHub Actions**입니다. 현재 사이트는 배포된 산출물이 기준이며,
이 저장소에는 생성된 웹 페이지나 별도 게시 브랜치를 두지 않습니다.

## Windows 업데이트 정보

다음 파일은 실제 게시된 GitHub Release의 설치 파일과 증분 업데이트를 가리킵니다.

- `windows-latest.json`: x64 업데이트
- `windows-arm64-latest.json`: ARM64 업데이트
- `windows/update.json`: 기존 x64 업데이트 주소를 사용하는 설치본의 호환 경로

새 Windows 릴리스를 공개하고 설치 파일·증분 파일의 해시를 검증한 뒤 이 파일들을 같은
`main` 변경으로 갱신합니다. x64 두 파일은 같은 내용을 유지해야 합니다. 비공개 소스의
웹 릴리즈 목록도 실제 공개 버전과 일치해야 사이트 배포 검증을 통과합니다.
파일 변경 후 웹사이트 배포를 실행해야 기존 사이트의 업데이트 URL에 반영됩니다.
앱이 사용하는 URL과 파일 형식은 저장소 브랜치 구성과 관계없이 유지합니다.
