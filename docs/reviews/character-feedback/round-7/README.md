# 7차 검토 — 하트 팝 한 번·채팅음 세 방향

[검토 페이지](index.html). 사용자의 정정에 따라 하트는 한 번 맞을 때 팝 한 번이다. 6차의 두 팝은 어시스턴트 해석 오류였다. A/B/C 음색은 바꾸지 않고 각각 첫 팝의 PCM만 남겼다. 오리 B·대포 C 및 기존 다섯 선택 원본·반복 WAV도 동일 바이트로 유지했다.

채팅 말풍선이 올라오는 순간의 소리도 세 가지로 제안한다.

- A: 물방울 톡, 0.16초. 짧은 물방울 공명을 직접 합성했다.
- B: 나무 톡, 약 0.09초. 기존 CC0 Kenney 나무 타격 소스를 부드럽게 편집했다.
- C: 작은 종 딩, 0.30초. 한 번의 맑은 차임과 짧은 여운을 직접 합성했다.

‘한 번 듣기’는 이벤트 한 번이다. ‘피격 3회 듣기’와 ‘채팅 3개 듣기’는 각각 별도 이벤트 세 번을 청취하는 버튼이며, 하트 한 번의 피격에 소리를 반복하는 것이 아니다. 비교 버튼은 A/B/C를 차례로 한 번씩 재생한다. 채팅 소리 후보 선택은 실제 앱 재생 정책 확정과 분리하며, 내 메시지 포함 여부·설정 통합은 구현 전에 확정한다. 확대음은 폐기 상태를 유지한다.

하트 출처·저자·CC0·파일 해시는 [6차 소스 기록](../round-6/sources/manifest.json), 나무 타격과 기존 선택 소리는 [4차 소스 기록](../round-4/sources/manifest.json)에 있다. 원본 파일을 중복 다운로드하거나 수정하지 않는다. 생성기는 이전 검토의 재사용 함수를 호출하며 이전 결과물을 덮어쓰지 않는다.

검증 통과: 하트 한 번 후보 3개, 채팅음 3개, 선택 원본 7개, WAV 총 28개. 하트가 정확히 6차의 첫 팝 PCM만 포함하는지 확인했다. 기존 일곱 음원의 원본 보존, 두 종류의 이벤트 구분, 파형 경계·peak 상한·재현성·반복/비교 PCM·파일 해시·HTML 링크·JavaScript 문법을 확인했다. 실제 청감과 브라우저 조작 검증은 사용자 검토 단계다. 새 음원은 앱에 적용하지 않았다.
