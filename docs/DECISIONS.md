# SIDEY 결정 기록

- 최종 갱신: 2026-08-31
- 관련 문서: [제품 기획서](PRODUCT_SPEC.md)

이 문서는 SIDEY의 제품·기술 결정을 추적한다. 구현과 다른 문서가 충돌하면 이 문서에서 `확정`으로 표시한 결정을 우선한다.

## 확정된 결정

| 항목 | 결정 | 이유 |
| --- | --- | --- |
| 제품명 | `SIDEY` | 사용자가 지정한 공식 작업명. `같이온`/`같이ON`은 사용하지 않음 |
| 앱 아이콘 | 흰색 반투명 라운드 사각형 안에 보라색·살구색의 둥근 두 캐릭터가 나란히 기대어 있는 사용자 제공 이미지 | 가까운 친구가 화면 곁에 함께 머무는 제품 성격을 단순한 형태로 표현하고 작은 아이콘에서도 두 실루엣을 구분할 수 있음 |
| 제품 형태 | 데스크톱 오버레이 Ambient Messenger | 일반 메신저보다 실제 친구가 화면 곁에 존재하는 경험에 집중 |
| 대상 플랫폼 | macOS 우선, Windows는 별도 클라이언트로 후속 개발 | macOS 네이티브 품질과 장시간 성능을 먼저 완성하고 Windows 일정과 구현을 분리 |
| macOS 클라이언트 | SwiftUI + AppKit + SceneKit, RealityKit 로더 검증 | 일반 창은 네이티브 UI, 오버레이 창 정책은 AppKit, 3D 런타임은 한 캐릭터 장시간 비용이 더 낮은 SceneKit이 담당하고 USDZ 호환성은 RealityKit 테스트로 함께 검증 |
| 백엔드 | Supabase | Auth, Postgres, Presence, Broadcast 사용 |
| macOS Supabase SDK | `supabase-swift` 2.55.1 exact SPM pin | 알파 빌드마다 SDK가 임의 갱신되어 세션·Realtime 동작이 달라지는 일을 막고 `Package.resolved`와 프로젝트 선언을 일치시킴 |
| 그룹 인원 | 최대 5명 | 작은 친한 친구 그룹에 집중하고 렌더링·UX 복잡도를 제한 |
| 사용자당 그룹 | 최대 5개, 한 번에 활성 그룹 하나만 표시 | 여러 친한 그룹을 지원하되 오버레이 복잡도와 렌더링 비용을 제한 |
| 그룹 이름 | 생성 시 1~20자로 입력, 방장이 변경 가능 | 그룹을 구분할 최소 관리 기능 |
| 캐릭터 설정 | 개인 프로필에 저장하고 모든 그룹에 동일하게 적용 | 그룹마다 정체성이 달라지는 혼란을 피함 |
| 캐릭터 중복 | 같은 그룹에서도 허용 | 캐릭터는 사용자를 식별하는 유일 키가 아니며 선택 자유를 우선 |
| 닉네임 중복 | 같은 그룹에서도 허용 | 사용자 식별은 UUID로 처리하며 표시명 선택 자유를 우선 |
| 초대 코드 | 방장이 재발급하기 전까지 유효 | 만료 UX를 단순화하고 유출 시 즉시 폐기 가능하게 함 |
| 방장 탈퇴 | 가장 먼저 참여한 남은 멤버에게 자동 이전 | 방이 관리 불능 상태가 되는 것을 방지 |
| 메시지 보관 | 30일 | 짧은 대화 기록은 제공하되 불필요한 장기 보관은 피함 |
| 인증 | 로그인 UI 없는 Supabase 익명 사용자 | 첫 실행 마찰을 낮추며 토큰은 OS 안전 저장소에 보관 |
| macOS 최소 버전·아키텍처 | macOS 26, Apple Silicon arm64 | Liquid Glass와 최신 SwiftUI·AppKit·RealityKit을 폴백 없이 사용하고 Intel 지원 비용을 제거 |
| macOS alpha 배포 | GitHub 사전 릴리스의 arm64 ZIP, Xcode Release 빌드의 ad-hoc 서명, 공증 없음 | 유료 Apple Developer Program 가입 전에도 초기 테스터에게 전달하되 미공증 상태와 Gatekeeper 수동 허용 절차를 명확히 고지 |
| macOS 정식 배포 | Developer ID 서명·Apple 공증을 완료한 설치 파일 | 일반 사용자에게 Gatekeeper 우회 없는 설치 경험을 제공하며 유료 개발자 계정 준비 후 진행 |
| 메시지 원본 | Postgres | 일시적인 연결 끊김에도 메시지를 잃지 않기 위함 |
| 메시지 전송 UX | 클라이언트가 UUID로 메시지를 즉시 낙관적 반영하고 Postgres 저장 결과와 조정하며, 실패 시 로컬 메시지를 제거하고 원문을 입력창에 복구 | 네트워크 왕복과 무관하게 말풍선을 즉시 보여주되 서버 원본성과 실패 복구를 유지 |
| 상태 전달 | Presence | 온라인, 자리 비움 등 비교적 느리게 변하는 상태에 사용 |
| Realtime 재연결 | 참여 중인 모든 방 채널이 구독돼야 연결 완료로 보며, 연결이 끊기면 transient 타이핑 상태를 즉시 폐기하고 Presence의 동일 키 `leave(old)+join(new)` 갱신에서는 새 join 상태를 우선 | 일부 방만 복구된 상태를 온라인으로 오판하거나 유실된 `typing_stop`과 이전 Presence leave가 화면 상태를 고착·덮어쓰는 일을 방지 |
| 그룹별 상태 | 사용자는 현재 활성 그룹에서만 온라인·자리 비움으로 표시하고, 참여 중인 다른 그룹에서는 오프라인으로 표시 | 한 번에 한 그룹에 머무는 경험을 명확히 하고 비활성 그룹에 잘못된 온라인 신호를 주지 않음 |
| 일시 이벤트 | Broadcast | 타이핑 등 저장할 필요 없는 이벤트에 사용 |
| 에셋 형식 | 제작·보관은 GLB 우선, macOS 런타임은 변환된 USDZ | GLB 전달 편의성을 유지하면서 Apple 네이티브 3D 프레임워크 지원 형식으로 재현 가능하게 변환 |
| 초기 검증 순서 | macOS 네이티브 캐릭터 1개 vertical slice 우선 | 오버레이·애니메이션·실시간 연결의 핵심 위험을 먼저 제거하며 Windows와 나머지 4개 캐릭터는 보류 |
| 타이핑 감지 범위 | SIDEY 입력창만 | 다른 앱의 입력 내용은 수집하지 않음 |
| 보안 표현 | E2EE 구현 전 종단간 암호화 주장 금지 | Supabase 전송·DB 보안은 E2EE와 다름 |
| 첫 캐릭터 에셋 | `minty_pup_station_v3_animated.glb` 기반 Minty Pup 데스크 모델 | 사용자 승인 외형을 유지하면서 캐릭터와 소품이 의미 단위로 분리되고 런타임용 모션을 포함함 |
| 구 데스크형 후보 에셋 | 캐릭터·의자·책상·노트북이 합쳐진 정적 GLB는 외형·성능 검증 기록으로만 보존하고 런타임에서 교체 | 생성형 원본의 의미 단위 분리가 불가능하고 skeleton이 없어 프로덕션 모션 구조로 사용할 수 없음 |
| 구 데스크형 후보 최적화 | 309만 triangle 원본의 20k triangle 감량본은 비교·회귀 자료로만 보존 | Meshy 50k remesh와 통짜 감량본 모두 분리·리깅 품질 한계가 확인됨 |
| 구 데스크형 리뷰 리그 | 통짜 후보 기반 5-bone 리뷰 리그는 동작 방향 검증을 마쳤으며 런타임에서 교체 | 573개 표면 조각의 변형 파손을 피하기 위해 승인된 분리 원본과 19-bone 리그로 대체함 |
| 현재 데스크형 런타임 에셋 | 크림색 Minty Pup, 파란 후드, 밝은 쿨 실버 노트북, 살구빛 크림 우드 책상·의자로 구성한 v3 stylized 승인본 사용. 털 roughness 중앙값은 약 0.79로 올려 플라스틱 광점을 줄이되 눈·코 광택은 유지하고, 책상 가로폭은 원본 대비 68.64%로 축소. 캐릭터 15,300 triangle, 소품 6,948 triangle, 19 bones, `online_idle`·`typing`·`away_sleep` 포함 | SceneKit에서는 따뜻한 키라이트와 부드러운 쿨 필라이트로 애니메이션 소품처럼 밝게 표현한다. 캐릭터가 정면을 보고 책상 상판 아래는 잘리는 오버레이 전용 구도를 사용하며 캐릭터·책상·의자·노트북을 독립 오브젝트로 유지해 이전 통짜 모델의 파손 문제를 제거함 |
| 모션 제작·재생 | Blender에서 제작하고 모션별 USDZ로 변환해 SceneKit에서 재생 | 생성형 프리셋에 의존하지 않고 macOS 네이티브 런타임에서 검증하며 변환 결과는 `usdchecker`와 RealityKit 로더 테스트도 통과시킴 |
| 개발 순서 | 모션별 승인 후 단일 캐릭터 기능 완성 | 나머지 캐릭터 4개는 MVP 외부 기능 이후 마지막에 추가 |
| 첫 모델 수면 얼굴 | 눈 감김은 보류하고 `Zzz` 효과만 사용 | 현재 GLB에 눈꺼풀 리그·blend shape가 없으며 외부 덮개 방식은 고개 각도에서 깨짐. 추후 눈꺼풀 포함 모델/에셋으로 교체 |
| 캐릭터 모션 상태 | `online_idle`, `typing`, `offline_sleep` 세 모션을 직접 전환 | 별도 전환 클립은 만들지 않고 포즈 튐 방지용 최대 0.15초 블렌드만 사용 |
| 오버레이 기본 배율 | 투명 창은 200% 영역으로 고정하고 캐릭터와 닉네임만 150~200% 범위로 조절하며 나머지 오버레이 UI는 160%로 고정 | 창 리사이즈와 재중앙 정렬로 인한 UI 떨림을 없애면서 캐릭터 크기 선택은 유지 |
| 오버레이 시각 구성 | 잠금 상태에도 자물쇠와 채팅 입력은 별도 Liquid Glass 패널에 항상 표시하고, 잠금을 풀면 이동·크기 조절·최근 기록·설정 조작을 같은 패널에 확장 표시 | 자주 쓰는 채팅과 잠금 전환은 즉시 접근하고 배치 변경 조작만 명시적으로 제한 |
| 하단 조작 패널 크기 | 잠금은 400×56, 편집은 580×56 논리 포인트로 사용 | 캐릭터 하단을 과하게 가리지 않으면서 잠금·입력·전송과 편집 조작의 최소 사용 폭은 유지 |
| 상태 표시 | 온라인·타이핑은 초록, 자리 비움은 주황, 오프라인은 빨강, 재연결은 점멸 회색 dot으로 표시 | 연결이 끝난 오프라인과 복구 중인 재연결을 색으로 즉시 구분하고 현재 상태를 일관되게 보완 |
| 그룹별 초대 코드 복사 | 설정의 각 그룹 행에 복사 버튼을 두고 이 기기 Keychain에 보관된 초대 코드 원문을 복사. DB의 해시에서는 원문을 복원하지 않음 | 초대 코드 평문을 서버에 저장하지 않는 보안 계약을 유지하면서 재초대 흐름을 단축 |
| 오버레이 조작 | 자물쇠와 채팅 입력은 항상 표시하며, 잠금 해제 시 이동·캐릭터 크기·최근 기록·설정 버튼을 추가 표시 | 기존 핵심 조작 흐름을 유지하면서 잠금 상태에서는 위치·크기 변경을 막음 |
| 오버레이 입력 | 네이티브 SwiftUI/AppKit 텍스트 입력으로 `Enter` 전송·`Shift+Enter` 줄바꿈과 최대 200자·3줄을 강제 | macOS IME의 표준 조합 처리를 유지하고 별도 key monitor 우회를 제거 |
| 최근 메시지 정렬 | 최근 기록 패널은 가장 최근 메시지를 맨 위에 표시 | 패널을 열자마자 새 메시지를 확인하고 아래로 갈수록 과거 기록을 읽게 함 |
| 말풍선 위치 | SceneKit에서 현재 캐릭터 스케일이 적용된 머리 상단을 화면 좌표로 투영하고 말풍선 하단을 그 위에 고정 | 캐릭터를 150~200%로 조절해도 말풍선이 머리와 겹치거나 과하게 떨어지지 않게 함 |
| 메뉴바 기능 | 오버레이 표시·잠금, 메시지 작성, 활성 그룹과 그룹별 미확인 수, 조용히 모드, 위치 초기화, 로그인 실행, 설정, 종료를 제공 | 오버레이를 직접 찾거나 설정창을 열지 않고 주요 상태와 조작에 접근하게 함 |
| 조용히 모드 | 캐릭터는 유지하되 새 말풍선을 표시하지 않고 그룹별 미확인 수와 아바타의 작은 점으로 알림 | 화면 공유·집중 작업 중 메시지 본문 노출을 막으면서 수신 사실은 보존 |
| 오버레이 클릭 영역 | 아바타·말풍선은 클릭 통과 패널, 입력창·편집 tray·기록은 별도 대화형 패널로 분리 | 전역 마우스 좌표를 수집하지 않으면서 투명 영역이 뒤 애플리케이션의 클릭을 가로채지 않도록 함 |

| 기존 세션 복구 실패 | 온보딩 완료 로컬 상태가 있으면 저장 세션 또는 기존 refresh token 없이는 새 익명 계정을 만들지 않고 설정창에 복구 오류를 표시 | 기존 방 접근권한을 새 계정으로 조용히 덮어써 사용자가 계정을 잃은 것처럼 보이는 상황을 방지 |
| 재실행 동작 | 온보딩 이후 수동 실행은 설정창을 앞으로 가져오고 로그인 자동 실행은 조용히 시작 | 사용자가 직접 실행했을 때 반응을 주되 로그인 시 반복 팝업을 피함 |
| UI 스타일 | macOS 26 네이티브 시스템 컨트롤과 Liquid Glass를 구조·탐색·상위 조작면에 적용 | 장식용 유리 효과 남용을 피하면서 플랫폼 일관성·가독성·성능을 확보 |
| 일반 창 UI | 설정은 약 1000×760의 리사이즈 가능한 일반 창과 `내 프로필`·`그룹`·`앱 설정` 사이드바를 사용하고, 본문 섹션은 시스템 `GroupBox`로 구분 | SwiftUI 네이티브 레이아웃·시스템 모서리·접근성 크기 조절을 사용해 수동 픽셀 배율과 장식용 Liquid Glass 카드 남용을 제거 |
| 온보딩 구성 | `닉네임·캐릭터`와 `그룹 연결`의 2단계로 나누고, 그룹 만들기와 초대 코드 참여는 상단 탭으로 전환하며, 완료 후 온보딩을 닫고 설정의 `그룹` 페이지로 이동 | 한 화면의 입력량을 줄이면서 두 가입 경로를 명확히 구분하고 생성·참여 결과를 바로 확인하게 함 |
