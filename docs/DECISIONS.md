# SIDEY 결정 기록

- 최종 갱신: 2026-09-05
- 관련 문서: [제품 기획서](PRODUCT_SPEC.md)
- 통합 브랜치: `main`; 작업 브랜치: `macos/*`, `windows/*`, `shared/*`

이 문서는 SIDEY의 제품·기술 결정을 추적한다. 구현이나 다른 문서와 충돌하면 여기서 `확정`으로 기록한 결정을 우선한다.

## 확정된 결정

| 항목 | 결정 | 이유 |
| --- | --- | --- |
| 제품명 | `SIDEY` | 공식 제품명이다. `같이온`·`같이ON`은 제품 문구, 코드, 식별자에 사용하지 않는다. |
| 제품 형태 | 최대 12명의 실제 친구가 2D 픽셀 동물로 화면 가장자리에서 함께 움직이는 초대 전용 데스크톱 ambient messenger | 고정형 채팅 목록보다 친구의 존재와 짧은 대화가 자연스럽게 보이는 경험에 집중한다. AI 동료나 가상 반려동물 제품은 아니다. |
| 공개 업데이트 문서 | README는 제품 소개 뒤 macOS·Windows 설치, 플랫폼별 최신 업데이트, 공통 향후 계획만 제공한다. GitHub Release와 `docs/releases/*`는 사용자에게 보이는 변화와 필요한 설치·제한 안내만 짧게 적고 DB·백엔드·클래스·빌드 구현 세부는 싣지 않는다 | README와 Release는 일반 사용자가 보는 문서다. 내부 변경이 사용자 경험을 뒷받침하면 `내부 안정성 개선` 또는 `내부 운영 구조 개선`처럼 결과만 설명한다. |
| 공개 향후 계획 | 새로운 말풍선 디자인, Windows 기능 안정화, 캐릭터 드래그 앤 드롭, 캐릭터 효과음, 다른 사람 캐릭터 클릭 이펙트를 향후 개선 후보로 공개한다 | 계획 항목은 구현 완료나 일정 약속이 아니며 현재 MVP 범위를 즉시 확장하지 않는다. 드래그 앤 드롭은 기본 클릭 통과 정책을 깨지 않는 별도 상호작용 설계가 확정된 뒤 구현한다. |
| 공식 다운로드 웹사이트 | GitHub 프로젝트 Pages `https://sidey-app.github.io/SIDEY/`를 한국어 기본·`/en/` 영어 정적 랜딩으로 운영하고 `website/`만 GitHub Actions로 배포. macOS는 현재 공증 DMG와 `sidey-app/tap/sidey` Homebrew Cask를 제공하고 Windows는 정식 Release Setup EXE를 직접 제공한다 | 앱 클라이언트나 별도 웹 기능을 추가하지 않고 공식 설치 경로·지원 환경·개인정보 경계·플랫폼 제한을 한곳에서 정확히 안내한다. Pages Actions가 버전에 맞는 Windows 정식 Release의 단일 설치 자산을 다시 내려받아 SHA-256을 계산한 뒤에만 다운로드 링크와 업데이트 manifest를 포함한 사이트를 배포한다. |
| 현재 구현 범위 | macOS production에는 유료 캐릭터 4종의 잠긴 상점을 배포하고, 격리된 `Sidey-dev`에서만 staging PortOne 테스트 결제를 허용한다. Windows 네이티브 `1.0.6`은 물체 던지기와 9종 캐릭터 렌더링, 반응형 설정 화면, 연결 복구, 그룹 나가기와 Setup EXE 설치를 제공한다. 무료 5종과 현재 계정에 활성 entitlement로 지급된 추가 캐릭터를 프로필에서 선택하고 추가 4종은 구매 동작 없는 상점 카드에서 미리 본다. | production 판매 개시와 결제 검증을 분리한다. Windows는 다른 사용자의 유료 캐릭터를 정확히 표시하고 추가 캐릭터를 숨기지 않되, 서버 소유권을 우회하는 선택이나 구매는 지원하지 않는다. |
| macOS 보유 꾸미기 장착 | direct판의 `내 프로필`은 현재 snapshot의 활성 entitlement로 확인한 말풍선·투척물만 종류별로 표시하고, 기본값 또는 보유 상품을 선택하면 프로필 저장과 분리해 계정의 모든 그룹에 즉시 적용한다. production은 상점 조회·구매 잠금을 유지하되 보유 상품의 장착·해제 RPC는 허용하고, App Store판에는 이 선택 영역을 표시하지 않는다. | 판매 잠금과 이미 지급된 사용권의 이용을 분리하면서 환불·회수 상품을 숨기고, 서버가 장착 시점에도 소유권을 재검증하게 한다. |
| macOS App Store 병행 배포 | 기존 Developer ID DMG·Homebrew판과 별도 bundle ID `app.sidey.desktop.appstore`의 Mac App Store판을 병행한다. App Store판은 네이티브 Sign in with Apple을 필수로 사용하고 StoreKit 2 비소모성 IAP로만 유료 캐릭터를 판매하며, Sparkle·PortOne·Google OAuth와 외부 구매 경로를 포함하지 않는다. direct판의 익명·Google 계정과 App Store판 Apple 계정은 이전·병합하지 않는다. | App Store의 Sandbox·로그인·디지털 상품 결제 규칙을 지키면서 현재 direct 배포와 세션을 건드리지 않는다. 두 앱은 Keychain·환경설정·구매 소유권을 분리하며 같은 사람이 같은 방에 두 계정으로 참가하면 두 명으로 계산한다. |
| App Store 계정 삭제 | App Store판은 설정에서 Apple 재인증을 거친 계정 삭제를 제공한다. 삭제 시 모든 방을 나가고 방장이면 가장 먼저 가입한 남은 멤버에게 소유권을 이전하며 마지막 멤버면 방을 삭제한다. 개인 데이터와 활성 entitlement 연결은 제거하되 법적·정산용 최소 거래 기록은 사용자 연결을 끊어 보존하고, 같은 Apple 구매 계정의 유효한 비소모성 구매는 새 SIDEY 계정에서 복원할 수 있다. | 계정 생성 앱의 삭제 의무를 충족하고 기존 commerce FK 때문에 유료 계정 삭제가 막히는 문제를 제거한다. 계정 삭제는 자동 환불이 아니며 Apple token 철회가 실패해도 SIDEY 데이터 삭제를 막지 않는다. |
| App Store 심사 UGC 범위 | 첫 App Store 제출은 초대 전용·최대 12명·7일 메시지 보관·방장 추방·고객지원이라는 현재 보호 장치로 심사를 시도하고 신규 신고·차단·본문 필터는 이번 구현에 추가하지 않는다. Guideline 1.2로 거절되면 문구만 바꿔 재제출하지 않고 해당 기능과 운영 처리 체계를 별도 결정·구현할 때까지 출시를 중단한다. | 현재 제품 범위를 임의 확장하지 않되, 신고·차단·필터가 없는 상태의 심사 거절 위험을 명시적으로 수용한다. |
| 플랫폼 순서 | macOS 정식판을 기준 구현으로 유지하고 Windows 11 25H2+ x64를 후속 개발 | 이미 배포된 macOS 코드를 재작성하지 않고 Windows 고유 창·DPI·전원·IME 리스크를 별도로 검증한다. |
| 플랫폼 브랜치 격리 | macOS 구현은 `macos/*`, Windows 구현은 `windows/*`, 문서·백엔드·웹·공통 계약은 `shared/*`에서 작업하고 `main`은 검증된 변경의 통합·배포에만 사용 | 한 플랫폼 작업이 다른 플랫폼 파일이나 다른 작업자의 dirty worktree를 건드리는 사고를 막는다. 공용 변경은 독립 커밋으로 만든 뒤 필요한 플랫폼 브랜치가 가져가며 반대 플랫폼 대응은 별도 후속 작업으로 남긴다. |
| 릴리스 운영 | 플랫폼별 공개 버전은 `release/macos.json`과 `release/windows.json`을 원본으로 사용한다. Windows 정식 배포는 `main`의 수동 `Windows Release` 하나만 실행해 draft Release를 만들고 내려받은 단일 Setup EXE가 CI 후보와 같은지 확인한 뒤 공개하며, 성공한 배포가 Pages를 직접 호출한다. macOS Developer ID·공증·Sparkle 개인키는 운영자 Mac에만 두고 `scripts/release_macos.sh` 한 명령이 패키징, draft 검증·공개, Pages 실행, signed appcast PR과 Homebrew Cask PR을 준비한다. | 태그·파일명·문서·업데이트 링크의 중복 입력과 태그 push·수동 실행의 이중 진입점을 없앤다. 공개 전 자산을 다시 검증하고 플랫폼 키를 CI에 올리지 않으면서도 후속 배포가 임의 워크플로 감시에 의존하지 않게 한다. |
| macOS 클라이언트 | SwiftUI + AppKit + SpriteKit | 일반 창은 SwiftUI/AppKit, 창 정책은 AppKit, 픽셀 월드는 SpriteKit이 담당한다. |
| Windows 클라이언트 | Windows 11 25H2(build 26200)+ x64, C#/.NET 10 LTS + WinUI 3/Windows App SDK 2.4.0 + Win32 | 일반 창은 WinUI 3, 투명 월드는 전용 Win32 HWND가 담당하며 실행 시 build 26200 미만은 지원하지 않는 환경으로 차단한다. `PixelCharacterCatalog`와 하나의 `UpdateLayeredWindow` 렌더러로 무료 5종과 유료 4종의 사전 생성 BGRA frame을 표시하고 별빛 우파루파에는 catalog 효과 플래그로 ambient sparkle과 pulse particle burst를 더한다. 프로필 선택 목록은 무료 5종과 서버에서 확인한 현재 계정의 활성 entitlement 캐릭터를 제공하고, 상점은 추가 4종을 정적 미리보기로 제공하되 구매 동작은 연결하지 않는다. 햄스터 1종 실기 계측은 같은 렌더러를 제한하는 Debug 전용 내부 모드이며 Release 제품 구현이나 별도 승격 전 구현 게이트가 아니다. 트레이·모니터·활동 감지는 Win32 플랫폼 서비스가 담당하며 WPF·Electron·WebView·Godot은 사용하지 않는다. |
| Windows 온보딩 확인 흐름 | 로컬 앱 설정을 초기화해도 Windows 자격 증명과 서버의 기존 프로필·그룹이 남아 있으면 온보딩 입력란에 복원하되 단계를 자동 진행하지 않는다. 사용자가 프로필의 `다음`과 그룹 생성·참여 또는 `건너뛰기`를 직접 선택하고 마지막 `SIDEY 시작`을 누른 뒤에만 온보딩 완료를 로컬 설정에 저장한다 | 복원된 서버 상태가 새 로컬 설치의 온보딩을 사용자 확인 없이 건너뛰지 않게 하면서, 이미 그룹이 있거나 당장 그룹을 만들지 않을 사용자는 중복 그룹 생성 없이 진행할 수 있게 한다. |
| Windows 설정 창 반응형 탐색 | 설정 창은 1000×760 DIP 안팎의 권장 크기로 열고 860×640 DIP까지 줄일 수 있다. 본문 너비가 줄어들면 왼쪽 탐색은 210 DIP의 제목·아이콘 보기에서 48 DIP 아이콘 레일로 자동 전환하며, 최소 폭에서도 아이콘 레일은 유지한다. 뒤로가기와 탐색 열기 버튼은 앱 제목과 함께 상단바에 두며 뒤로가기는 실제 방문 이력을 따른다. 최소 크기는 사후 보정이 아니라 Win32 native tracking constraint로 강제한다 | 좁은 창에서 고정 사이드바가 본문을 압박하지 않게 하면서 탐색 항목과 연결 상태를 계속 확인할 수 있게 한다. WinUI `TitleBar`·`NavigationView`의 표준 배치와 애니메이션을 사용하고, 최소 크기에서 계속 드래그할 때 반복 resize로 화면이 깜빡이지 않게 한다. |
| Windows 연결·셸 피드백 | 설정 탐색 푸터는 펼친 카드와 축소 점을 한 자리에서 전환하고, 펼친 상태의 점과 문구는 한 행에서 시각적으로 중앙 정렬한다. 축소 시작 시 문구를 즉시 숨기고 펼침 시작과 함께 짧게 fade-in하며, 축소 상태는 카드 배경 안에서 아이콘 레일 중앙에 맞춘다. 연결 실패는 빨간 점과 `연결 안 됨`으로 표시한다. 최초 연결과 정상 연결 뒤의 재단절 모두 15초 동안 시스템 알림을 유예하고 그 안에 복구되면 취소한다. 복구되지 않은 장애는 한 번만 알리되 짧은 재연결 반복은 15분 cooldown으로 제한한다. 트레이 메뉴 맨 위 기본 항목은 굵은 `열기`이고 종료 문구는 `종료`다. 월드와 모든 캐릭터 입력 hotspot은 작업 표시줄·Start·검색·트레이 팝업보다 뒤에 유지한다 | 시작과 일시적인 네트워크·Realtime 복구 시간을 장애로 오인하지 않으면서, 지속되는 실패는 창이 숨겨져 있어도 알리고 반복 알림은 피한다. 탐색 전환 중 잘린 연결 문구나 중복 점을 노출하지 않고, 보이는 캐릭터와 투명 입력 창의 Z-order를 함께 갱신해 Windows 셸 위에서 클릭·우클릭을 가로채지 않게 한다. |

| Windows 서명 | 공인 코드 서명 인증서를 도입하기 전에는 SIDEY 제작 실행 파일·DLL·Windows 설치 파일을 자체 서명하지 않고, Release에 자체 서명 인증서를 제공하거나 설치하도록 안내하지 않음 | 신뢰되지 않은 자체 서명 인증서 설치를 사용자에게 요구하지 않는다. 공인 인증서 도입은 별도 검증 후 결정한다. |
| Windows 설치·업데이트 | `1.0.6` Setup EXE는 같은 버전에서 복구·제거·닫기, 새 버전에서 기존 설치 위치 재사용, downgrade 차단, 기존 정식 MSI의 무인 제거 후 사용자 데이터 보존 전환을 지원한다. 신규 설치와 새 버전 업그레이드에서는 `website/terms.html`의 이용약관을 표시하고 필수 동의 체크박스를 선택해야 진행할 수 있다. 복구·제거에는 다시 동의를 요구하지 않는다. 일반 제거에는 현재 사용자의 설정·로그와 로그인 자격 증명을 각각 삭제하는 기본 미선택 옵션을 제공한다 | v1.0.3·v1.0.4는 검증용 파일 스트림을 닫기 전에 설치 파일을 이동해 앱 내 다운로드가 실패하므로 최신 Setup EXE를 수동 설치해야 한다. 기존 per-user·Burn 테스트 설치는 먼저 제거한다. 웹 약관 본문을 패키징 시 설치기용 텍스트로 변환해 공개 약관과 설치기 사본의 내용 불일치를 막고, 유지관리 작업은 새 설치 계약으로 취급하지 않는다. 선택한 일반 제거 항목만 `%LOCALAPPDATA%\SIDEY`와 Credential Manager의 `SIDEY/` 정보를 삭제하며 upgrade·repair·MSI 전환은 보존한다. 업데이트는 `windows-v<version>`의 버전에 맞는 고정 설치 파일 URL과 manifest 내부 SHA-256이 유효할 때만 사용자 승인을 받아 다운로드·검증한 뒤 설치기를 실행하며 무인 자동 설치는 하지 않는다. Release에 별도 `.sha256` 파일은 두지 않는다. |
| Windows 시작 안정성 | 앱 시작과 실행 진단을 `%LOCALAPPDATA%\SIDEY\Logs\SIDEY.<underscore-version>.<yyyyMMdd>.<HHmmss>.log` 세션 파일 하나에 기록하고, WinUI 초기화 예외는 사용자에게 로그 경로를 표시한다. 트레이 초기화 실패만으로 프로세스를 종료하지 않고 이때는 창 닫기가 앱 종료로 동작하며 CI가 게시된 `SIDEY.exe`를 실제 시작해 창 활성화 단계까지 확인한다 | 기존 CI는 파일 존재만 검사해 시작 직후 예외와 누락된 런타임을 잡지 못했다. 사용자에게 아무 반응도 없는 종료를 없애고 설치 후보 자체를 실행 검증하며, 시작과 실행 중 문제를 같은 시간축에서 확인한다. |

## 현재 검증 기준

- 4개 가장자리 × 3개 길이의 activity/render 영역, 중앙 정렬, 회전, 상단 닉네임·상태 점·메시지·타이핑 본문의 정방향 표시, visible frame, hotspot 원점 변환, 모니터 제거 fallback이 단위 테스트를 통과해야 한다.
- 제품 방은 12명으로 제한하되 20개 합성 노드가 3,000 tick 동안 track 밖이나 NaN 상태로 빠지지 않는 스트레스 테스트를 통과해야 한다.
- 상태 전환, 주황 `Zzz`, 오프라인 숨김, 방 전환 UUID diff, 최대 8자 닉네임·반투명 배경과 상태 점 간격, 캐릭터 겹침 시 idle 해제·가속 통과, 실제 메시지 말풍선 스택의 8pt 분리·72pt/s 제한·경계 힘 재배분·혼잡 안정성, 타이핑 말풍선 제외, 7배·0.8초 더블클릭 리액션의 1초 제한·Broadcast 중복 제거, 발신자별 최신 2개·세 번째의 가장 오래된 본문 제거·12명×2개·개별 만료·이동 중 추적을 검증한다.
- 실서버 2클라이언트 테스트에서 한쪽 WebSocket을 강제로 끊은 뒤 재실행 없이 자동 재구독하고 메시지·Presence·`character_pulse` 수신을 복구해야 한다.
- 월드는 항상 위이며 전체 영역의 클릭 통과를 유지한다. 내 캐릭터 hotspot과 입력창만 포인터를 받고 입력창만 키보드 포커스 가능하며, 마지막 전송 뒤 5초 유지·타이머 갱신·실패 복구를 지키고 최근 기록은 일반 창이어야 한다.
- Sparkle 프레임워크와 `SUFeedURL`·`SUPublicEDKey`가 Release 번들에 포함되고 signed feed·압축 해제 전 검증이 강제되어야 한다. appcast 게시 도구는 ad-hoc·development 빌드를 기본 거부하고 Developer ID·Hardened Runtime·stapled notarization·production 표시명과 채널을 검증해야 한다. development 채널은 Sparkle을 만들지 않고 업데이트 메뉴를 비활성화해야 한다.
- 12번째 가입 성공, 13번째 거부, 여섯 번째 방 거부, 7일 초과 메시지 삭제, 방장 전용 이름 변경·추방·삭제와 cascade, RLS, 중복 닉네임·캐릭터 허용을 SQL 테스트한다.
- 최대 방 인원 12명으로 30분 실행하고, 별도 20노드 합성 부하에서도 p95 frame time 40ms 이하, 100ms 이상 main-thread hang 없음, 지속 RSS 증가 없음, 숨긴 월드의 SpriteKit 정지를 확인한다.
- Windows는 무료 5종과 현재 계정의 활성 entitlement 캐릭터 선택, 추가 4종의 구매 없는 상점 미리보기와 원격 렌더링을 같은 catalog·renderer asset으로 유지하고 Debug 전용 햄스터 제한 모드에서 투명·최상위·클릭 통과·52×52 hotspot·DPI·잠금·절전 복귀를 실기 검증한다. 연결형 검증은 익명 세션·방·Presence·타이핑·메시지·`character_pulse`·`character_throw`를 macOS와 양방향 확인한다.
- Windows 정식판은 12명 2시간과 20노드 30분 부하에서 p95 frame time 40ms 이하, 100ms 이상 UI-thread hang 없음, warm-up 후 working set 20MB 초과 증가 없음, handle·surface 지속 증가 없음을 확인한다.
