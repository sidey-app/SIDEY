## 확정된 결정

2026-09-11 사용자가 `두 수정안 모두 반영`으로 round-4 왁뿌볼·두쫀쿠를 승인했다. 왁뿌볼은 얇은 외곽과 하이라이트를 통해 분홍 내용물이 비치는 껍질을 표현하고, 충돌 시 여러 작은 파편으로 흩어진다. 두쫀쿠는 둥근 코코아 겉피와 눌림·늘어나는 속을 유지한다. 두 192×16 시트를 승인 원본과 macOS 두 타깃에 교체하며 확정 음원은 바꾸지 않는다. 이전 round-4 승인 대기를 대체한다.

2026-09-11 추가 검토에서 상점 투척물 자동 미리보기에도 충돌 효과음을 재생하도록 변경한다. 기존 로컬 효과음 설정과 동시 재생 제한·종료 정리는 그대로 따른다. 나무의 정지/걷기 조작 안내는 상품 상세에서 한 번만 표시한다. 사용자는 왁뿌볼 충돌을 여러 껍질 조각으로 부서지는 표현으로, 두쫀쿠를 더 둥근 외형으로 다시 제작해 승인받도록 요청했다. 새 원화는 `round-4` 후보로 격리하며 사용자 승인 전 앱 번들·승인 원본에 교체하지 않는다. 왁뿌볼 A와 두쫀쿠 승인 음원은 그대로 유지한다.

2026-09-11 후속 요청으로 macOS 프로젝트를 Xcode에서 열고 App Store 심사 후보와 Sandbox·Production StoreKit 결제 경로를 준비한다. 사용자는 새 상품 7종이 아직 App Store Connect에 등록되지 않았음을 확인했고 등록 준비도 이번 범위에 포함한다. 조개·돼지고기·작은 나무는 캐릭터에 포함되는 기본 투척물로 별도 판매하지 않는다. 실제 상품 등록·가격 포인트·심사용 스크린샷·Apple 계정 연결·서버 catalog 반영·구매 및 복원 검증이 끝나기 전에는 심사 준비 완료로 표시하지 않는다. 공개 릴리스와 심사 제출은 실행하지 않으며 direct production 판매 잠금도 유지한다. 신규 콘텐츠 추가에 따라 양쪽 macOS 후보의 마케팅 버전은 1.2.0으로 맞춘다. build 27은 로컬 후보 번호이며 업로드 전에 양쪽 채널의 실제 사용 이력과 대조한다.

2026-09-11 사용자가 돼지고기 `촵` 2차(0.24초)까지 최종 승인했다. macOS 직배포판과 App Store판에 새 캐릭터·고유/별도 투척물·승인 음원·나무 우클릭 정지/걷기를 반영하고 Sidey-dev를 빌드·실행한다. App Store판에도 기존 효과음 설정·4동시/80ms 제한·잠금/숨김 정지를 적용한다. Sidey-dev 검토는 Debug 전용 로컬 테스트 방으로 제공해 서버 소유권을 우회하지 않는다. 공개 릴리스·스토어 제출·운영 판매 활성화는 하지 않는다.

2026-09-11 사용자는 수달·돼지·나무 및 고유·별도 투척물의 시각과 돼지고기를 제외한 소리를 승인했다. 왁뿌볼은 3차 A 원본으로 확정한다. 돼지고기만 짧은 `챱` 접촉음으로 수정해 승인받고 macOS 직배포판·App Store판 양쪽에 반영한다. 수달·돼지·눈송이·야구공·두쫀쿠는 전부 유료이며 직배포 990원, App Store 1,100원이다. 나무·왁뿌볼은 직배포 1,900원, App Store 2,200원을 유지한다. 고유 투척물은 캐릭터 기본 투척물에 포함한다. 이 결정은 해당 구현의 승인으로서 이전 후보 전용·앱 미적용 범위를 대체하며, 돼지고기 음원 승인 전 실제 앱 적용은 기다린다. 기존 운영 판매 잠금 해제나 공개 릴리스는 별도다.

2026-09-11 두쫀쿠 충돌음은 별도 둔탁한 타격음 레이어를 제거하고 바삭한 속 소리만 재생한다. 고유 투척물 후보는 수달 조개, 돼지 돼지고기 한 점, 나무 작은 나무 한 그루로 제작한다. 돼지·나무 물건은 사용자 지정이며 수달 조개는 나뭇가지와의 시각 구별을 고려한 제안이다. 최종 앱 연결·판매 등록은 별도다.

2026-09-11 나무 캐릭터와 왁뿌볼 투척물은 각각 macOS 직배포판 1,900원, App Store 2,200원으로 가격을 확정한다. 사용자는 나무 우클릭으로 정지하고 다시 우클릭하면 걷는 전환을 요청했다. 사용자는 던지기 활성화를 더블 우클릭으로 바꾸기로 확정했다. 단일 우클릭 판정은 시스템 더블 클릭 시간만큼 지연해 첫 클릭의 정지/걷기 동작과 충돌하지 않게 한다. 설정 ON에서는 더블 우클릭 뒤 기존 10초 활성화와 0.5초 쿨타임을 유지하며 OFF에서는 친구를 바로 클릭한다. 눈송이·야구공·왁뿌볼은 별도 제작된 후보 3종이며, 고유 투척물의 최신 후보 연결은 위 결정에 따른다. 추가로 요청한 두쫀쿠도 회전·충돌 시트와 소리를 제작하되 가격·고유 연결은 미정이다. 가격 확정은 최종 그림·음원 선택이나 판매 활성화를 대신하지 않는다.

2026-09-11 후보 3차: 사용자는 기존 캐릭터의 눈·목도리와 걷기 프레임 구성을 다시 대조하고, 왁뿌볼을 더 굵은 파쇄 질감의 5안으로 준비하라고 요청했다. [3차 후보](../assets/candidates/otter-pig-tree/round-3/README.md)는 승인 햄스터의 눈 패턴과 1px 윗몸 이동·발 고정을 기준으로 한다. 나무 뿌리 고정과 앱 미적용 범위는 유지한다.

2026-09-11 후보 2차: 사용자는 프레임 넘기기 버튼 제거, 상태별 동작 검토, 기존 캐릭터와 비슷한 낮은 시각 밀도, 투척물 3종의 소리 동시 검토를 요청했다. 특히 왁뿌볼은 ASMR의 연속적인 ‘와그작’ 껍질 파쇄를 분석해 재현하는 방향이다. [2차 후보](../assets/candidates/otter-pig-tree/round-2/README.md)에 단순화한 ImageGen 캐릭터와 로컬 충돌음 후보를 보관한다. 이번 음원은 후보이며 기존 승인음·앱에 적용하지 않는다.

2026-09-11 수달·돼지·나무 캐릭터와 눈송이·야구공·왁뿌볼 투척물의 신규 후보 제작을 진행한다. PR #27 그림을 재사용하지 않고 ImageGen 원화·규격 시트·로컬 검토 페이지·전체 프레임 비교표·움직이는 미리보기를 [별도 후보 폴더](../assets/candidates/otter-pig-tree/round-1/README.md)에 보관한다. 나무는 뿌리를 고정하고 걷기 슬롯 2–5를 제자리 흔들림으로 채우며 검토 페이지에서 수평 이동·방향 반전을 적용하지 않는다. 이번 확정은 후보 제작 범위에 한정한다. 승인 에셋·기존 PR·앱 코드·상품·가격·플랫폼 배포 복사본은 변경하지 않으며 무료/유료와 캐릭터별 기본 투척물은 미정이다. 실제 앱의 나무 고정은 캐릭터별 이동 정책을 추가하는 별도 후속 작업이다.

사용자는 하트 7차 B(팝 한 번)를 최종 선택하고 채팅 말풍선 소리를 폐기했다. 승인된 피격음 8종만 기절과 함께 macOS 직배포판에 연결한다. 확대·채팅음은 모두 제외한다. 기본 ON 소리 스위치·직배포 schema 9·4개 동시 재생·80ms 시작 제한은 유지한다. 사용자가 직접 때려볼 수 있도록 Debug 직배포 전용 로컬 테스트 방과 상대 캐릭터 한 명, 8종 투척물 선택을 준비하고 Xcode를 연다. 이 테스트 방은 서버 계정·실제 방을 생성하지 않는다. 최종 WAV와 SHA-256은 audio-approval.json에 기록한다.

7차 수정: 사용자는 하트를 한 번 맞을 때 팝 한 번으로 명확히 정정했다. 이전 6차의 두 팝은 어시스턴트의 해석 오류이며 폐기한다. 기존 세 음색 각각의 첫 팝만 남기고 음량을 유지한다. 새 채팅 말풍선이 올라왔을 때의 소리도 서로 다른 3개 시안으로 추가 요청했다. 이번 단계는 음원 방향 검토이며 적용 전 승인을 받는다. 오리 B·대포 C를 포함한 기존 7종 선택과 확대음 폐기는 유지한다.

6차 음원 결정: 사용자가 오리 5차 B·대포 5차 C를 선택했다. 이전에 고른 다섯 피격음과 함께 원본·음량 그대로 확정한다. 하트만 입술을 터뜨리는 `뾲뾲` 질감으로 다시 제작하며, 한 번 피격에 짧은 팝 두 번인 3개 후보를 제출한다. 새 하트는 적용 전 선택·승인을 받는다. 확대음 폐기는 유지한다.

2026-09-10 5차 음원 결정: 확대 효과음 기획을 폐기한다. 캐릭터 확대 동작 자체는 유지한다. 말랑공 A·미니 파프리카 C·바나나 B·먼지목욕 모래주머니 C·별빛 구슬 B는 4차 원본과 음량 그대로 선택 확정한다. 통통 하트는 미선택이며 수정 요청이 없어 4차 후보를 유지한다. 오리와 대포만 각 3안으로 재제작한다. 오리는 한 번 맞을 때 꽥 한 번만, 대포는 깨지는 질감 대신 낮은 울림의 충돌 폭발음으로 다듬는다. 새 후보의 앱 적용 승인은 별도로 받는다.

macOS 직배포판 프로필의 캐릭터·말풍선·투척물 선택 표시는 기존 캐릭터 기준인 보라색(RGB 0.45/0.49/0.85) 3pt 테두리·동일한 원형 체크·선택 배경으로 통일한다. 장착 요청 중 스피너와 확정 선택 구분, 키보드 focus는 유지한다. App Store·Windows 구현은 이번 수정 대상이 아니다.

기절 선행 구현과 승인된 피격음 8종·소리 설정·선택 테두리 통일을 `macos/v1.1.0-release`에 통합했다. 하트는 7차 B의 단일 팝이며 채팅·확대음은 폐기했다. Debug 전용 `SIDEYFeedback` scheme은 로그인 없이 나와 콩이가 있는 로컬 검증 방을 연다. 이 방은 Release에 포함되지 않는다.

2026-09-10 사용자가 “효과음 내일 이어서 … 우선 기절쪽만 구현”을 지시했다. 이를 현재 별·링 V2와 기존 수면 모션을 사용하는 기절 구현의 승인으로 기록한다. 기절을 효과음과 분리해 macOS 직배포판에 먼저 구현한다. 10초 내 10회·6초 기절·보호 시간 없음은 유지한다. 효과음·소리 설정·설정 schema 변경은 보류하며 기절 구현에 포함하지 않는다. 앞선 음원·시각 일괄 승인 후 구현 순서보다 이번 분리 지시가 우선한다.

2026-09-10 피드백으로 피격음 8종을 모두 재제작한다. 모든 소리는 던지기·비행이 아니라 맞는 순간의 반응이다. 오리는 알아들을 수 있는 `꽥꽥`, 대포는 충돌 시 `펑` 폭발을 사용한다. 나머지도 타격의 시작을 선명하게 만들고 상승 멜로디를 사용하지 않는다. 4차는 각 3개, 총 24개 피격 후보를 다시 승인받는다. 기존 말랑공 C 선택은 과거 파일에 대한 기록이며 새 후보의 승인이 아니다. 확대 C 기반 3안과 별·링 V2는 변경하지 않고 검토를 이어간다. 아래 3차 말랑공 유지 방침보다 이 재작업 결정이 우선한다.

3차 효과음 검토 당시 사용자는 말랑공과 확대 모두 2차 C를 선택했다. 말랑공 `hit-c-v2`는 동일 파일·음량으로 유지하고, 확대는 C의 8비트 음색·네 음을 유지하면서 각 음이 더 오래 들리는 0.36초·0.48초·0.62초 후보를 제출한다. 나머지 투척물 7종은 각각 3개 후보를 함께 검토한다. 말랑공 외 신규 후보와 링을 포함한 최종 시각 승인은 대기하며 앱 적용 전 승인 절차는 유지한다.

직배포판 기절의 별 회전은 1차 시안의 모양·위치·1.2초 주기를 유지하고 궤도를 잇는 얇은 픽셀 링을 추가한 후보로 다시 검토한다. 말랑공 피격음은 끝 음이 낮아져 힘이 빠지는 인상을 제거하고 발랄하고 귀여운 탄성을 우선한다. 확대음은 유사한 변형 3개 대신 풍선 장난감·마법 종소리·8비트 레벨업의 서로 다른 분위기 3개를 제출하고 사용자가 선택한 방향을 다듬는다. 이는 제작 방향의 확정이며 변경 에셋의 최종 적용 승인은 아직 아니다.

macOS 직배포판에 투척물별 피격음 8종·공통 확대음 1종과 기본 ON인 로컬 `캐릭터 효과음` 설정을 추가하기로 확정했다. App Store판·Windows·공개 웹은 이번 구현 대상이 아니다. 현재 그룹에 표시되는 모든 캐릭터의 실제 충돌·확대에 재생하며 조용히 모드와 독립적으로 제어한다. 아직 구현·배포된 기능이 아니며, 음원과 기절 PNG·애니메이션을 함께 사용자에게 제출해 각각 명시적으로 승인받은 뒤에만 앱에 적용한다. 일반 구현 지시는 에셋 승인을 대신하지 않는다. 후보는 `assets/v1` 승인 원본이나 앱 번들에 포함하지 않는다.

직배포판의 기절은 대상 UUID별 실제 충돌을 합산해 최근 10초 이내 10회에서 발동하고 6초간 유지한다. 기절 중 피격은 시간을 연장하거나 다음 횟수에 누적하지 않는다. 회복 후 보호 시간 없이 즉시 0회부터 누적한다. 기존 웅크린 수면 2프레임과 노란 픽셀 별 3개를 사용하고 Zzz를 숨긴다. 자기 캐릭터의 확대·던지기는 기절 중 잠그되 채팅은 유지한다. 각 화면에서 판정하며 서버 API·Presence를 변경하지 않는다. 상세 계약과 승인 상태는 [직배포판 캐릭터 피드백 작업 기록](reviews/character-feedback/PLAN.md)에 둔다.

Windows 설치·복구·제거 UI는 영어·한국어·일본어·중국어 간체/번체·러시아어·우크라이나어를 제공한다. 설치 시작의 언어 선택 목록은 현재 사용자의 Windows 표시 언어를 맨 위에 두고 나머지는 영어 언어명 알파벳순으로 표시한다. 지원하지 않는 표시 언어에서는 전체 목록을 알파벳순으로 두고 영어를 기본 선택한다. 기존 설치의 명시적 언어 선택은 업데이트와 제거에서 유지한다. 약관 본문은 기존 공개 한국어 원문을 사용하며 앱 내부 지원 언어와 설치기 지원 언어는 독립적이다.

Windows의 아이콘·캐릭터·말풍선·투척물 파일은 설치 루트의 `Assets` 한 곳에 둔다. XAML에서 사용하는 제목 표시줄 아이콘도 설치 루트에서 읽으며, `Runtime/Assets` 사본은 만들지 않는다. 컴파일된 XAML/PRI는 실제 호스트 옆에 유지한다.

Windows의 다음 배포부터 unpackaged·multi-file framework-dependent 방식을 사용한다. .NET 10 x64 Runtime과 Windows App SDK / WinUI 공유 런타임은 SIDEY 설치 파일에 포함하지 않는다. 설치기는 필요한 런타임을 확인하고 누락 시 공식 Microsoft 배포 경로에서 받아 설치·검증한 뒤에만 기존 SIDEY를 종료·제거하고 새 앱을 설치한다. prerequisite 실패·취소·재시작 필요 시 기존 앱 제거를 시작하지 않는다. 기존 self-contained 설치의 앱 전용 Runtime 파일은 교체 시 정리하며, 시스템 공유 런타임은 SIDEY 제거 대상이 아니다. 기존 NSIS 설치 위치·복구·삭제 옵션·MSI 전환과 자동 업데이트 계약은 유지한다. 아래 현재 공개본의 self-contained 배포 기록은 이전 버전에 대한 설명이다.

Windows 영어·일본어 문구는 기능·제한의 뜻을 유지하면서 현지 앱에서 자연스러운 표현, 동물 이름과 일상 대화 예시를 사용한다. 날짜·시간은 앱 언어와 무관하게 컴퓨터의 지역 형식과 시간대 설정을 따른다. 숫자 표시는 선택한 언어의 표기 관례를 따르며 원화 결제 금액은 바꾸지 않는다. 상점 미리보기의 투척물·발사대·충돌 효과는 프레임별 기본 이미지 컨트롤을 미리 준비해 표시하며, 실제 미리보기 대화상자에서 합성된 픽셀 유무를 내부 검증한다.

Windows 설정 페이지 맨 아래에는 설명 왼쪽·한국어·English·日本語 드롭다운 오른쪽의 언어 설정 행을 둔다. 선택은 로컬 설정에 저장한 뒤 재실행 없이 즉시 적용한다. 창·오버레이·연결을 다시 만들지 않고 문구를 갱신하며 입력 중인 초안과 현재 선택을 유지한다. 처음에는 기존 시스템 UI 언어 감지를 유지한다. 그룹 페이지는 활성·비활성 모두 같은 기본 사람 아이콘을 사용하고 활성은 민트색, 비활성은 회색으로 구분한다. 활성 상태에서도 아이콘 모양이나 내부 채움은 바꾸지 않는다.

Windows 앱과 런처는 시스템 UI 언어의 한국어·영어·일본어를 지원한다. 공통 기능의 문구는 macOS와 뜻을 맞추되 Windows 설치·업데이트 등 플랫폼별 안내는 유지한다. 상점 캐릭터 미리보기에는 조작 안내 문장을 별도로 표시하지 않고, 확대 중에도 닉네임을 캐릭터 앞에 표시한다.

Windows 오버레이와 상점 캐릭터 미리보기의 산책은 macOS와 같은 도착·휴식·상태별 정지 규칙을 따른다. 상점 캐릭터 미리보기는 상품 캐릭터를 더블클릭하면 발 위치를 고정한 채 3배로 확대했다가 복귀하고, 친구 캐릭터를 클릭하면 상품 캐릭터의 투척물을 던진다. 빈 무대 클릭은 동작하지 않는다. 별빛 우파루파 미리보기는 평상시 반짝임과 확대 시 섬광·두 겹의 반짝임을 모두 표시한다. 미리보기 상호작용은 로컬에서만 재생하고 서버 이벤트를 보내지 않는다.

## 현재 검증 기준

- 4개 가장자리 × 3개 길이의 activity/render 영역, 중앙 정렬, 회전, 상단 닉네임·상태 점·메시지·타이핑 본문의 정방향 표시, visible frame, hotspot 원점 변환, 모니터 제거 fallback이 단위 테스트를 통과해야 한다.
- 제품 방은 12명으로 제한하되 20개 합성 노드가 3,000 tick 동안 track 밖이나 NaN 상태로 빠지지 않는 스트레스 테스트를 통과해야 한다.
- 상태 전환, 주황 `Zzz`, 오프라인 숨김, 방 전환 UUID diff, 최대 8자 닉네임·반투명 배경과 상태 점 간격, 캐릭터 겹침 시 idle 해제·가속 통과, 실제 메시지 말풍선 스택의 8pt 분리·72pt/s 제한·경계 힘 재배분·혼잡 안정성, 타이핑 말풍선 제외, 7배·0.8초 더블클릭 리액션의 1초 제한·Broadcast 중복 제거, 발신자별 최신 2개·세 번째의 가장 오래된 본문 제거·12명×2개·개별 만료·이동 중 추적을 검증한다.
- 실서버 2클라이언트 테스트에서 한쪽 WebSocket을 강제로 끊은 뒤 재실행 없이 자동 재구독하고 메시지·Presence·`character_pulse` 수신을 복구해야 한다.
- 월드는 항상 위이며 전체 영역의 클릭 통과를 유지한다. 내 캐릭터 hotspot과 입력창만 포인터를 받고 입력창만 키보드 포커스 가능하며, 마지막 전송 뒤 5초 유지·타이머 갱신·실패 복구를 지키고 최근 기록은 일반 창이어야 한다.
- Sparkle 프레임워크와 `SUFeedURL`·`SUPublicEDKey`가 Release 번들에 포함되고 signed feed·압축 해제 전 검증이 강제되어야 한다. appcast 게시 도구는 ad-hoc·development 빌드를 기본 거부하고 Developer ID·Hardened Runtime·stapled notarization·production 표시명과 채널을 검증해야 한다. development 채널은 Sparkle을 만들지 않고 업데이트 메뉴를 비활성화해야 한다.
